# hydg02

HY-DG02 主控上的应用程序。

```sh
git clone https://github.com/Roleran/hydg02.git
```

功能以《HY-DG02 整机功能列表》为准。注册成功之前，不播报、不亮屏、不响应触发、不转发串口。

## 章节

| 章 | 功能 | 状态 |
|---|---|---|
| 1 | 上电上云 | 程序已实现，待板上联调 |
| 2 | 语音播报 | 程序已实现，待板上联调 |
| 3 | 语音对讲 | 程序已实现，待板上联调 |
| 4 | LED 文字 | 程序已实现，屏控固件未改 |
| 5 | 触发与定时 | 程序已实现，雷达上报未改 |

| 7 | 升级、远程重启、恢复出厂 | 程序已实现，待板上联调 |

下一版不做：摄像机人车识别、烟火识别和算法升级。

上面 7 章可以按本章命令和平台对接。PC 上的 `--selftest` 只核对报文，不代替实机。4G、喇叭、麦克风和两路 485 还要在板上确认。屏的点阵和雷达上报在屏控 N32 上，那边现在仍是演示程序，没有按第 4 章解析串口帧，所以亮屏和雷达触发要等屏控改完才能联调。

### 和参考协议已经定下来的差异

《MQTT 协议 2.0.0》只作参考。注册的 `0x81`、`0x01` 和 Topic 与参考协议相同。下面这些地方参考协议没写清，或者和整机功能列表不一致，以本文件为准。

| 事项 | 参考协议 | 本期 |
|---|---|---|
| 定位 | 启动后再每 5 分钟上报 | 只在注册成功后上报一次。没有定位也报一帧，有效标志为 0 |
| MQTT 地址 | 要求先取 HTTP 地址，没写正文格式 | 正文第一行是 `主机:端口`。`http_url` 为空时用配置里的实验台地址 |
| 业务命令号 | 没有定义 | 第 2 章到第 7 章的命令号 |
| 语音文件 | 只写 MP3，多个文件循环播 | WAV、MP3、PCM、OPUS。一次触发按槽位 1、2、3 各播一遍后停止 |
| 对讲 | 主板侧按 WebRTC 或国标 SIP | 浏览器仍走 ZLMediaKit 的 WebRTC。主板因 4G 在 NAT 后面，只收发 16 kHz PCM 的 RTP |

| 屏上的字 | 点阵还是文字，当时未定 | 平台下发 UTF-8，点阵由屏控字库生成 |
| RS485 | 未定多个设备怎么区分 | 平台指定两路中的一路。地址写在报文里，主板不解析 Modbus |
| 校时 | 未定主板时间是否准 | 本期不改系统时间。定时用主板本地时间 |
| 人车、烟火、算法包 | 协议 3.6、3.10、3.11 | 下一版。触发方式可以先切到摄像机，切过去之后雷达不再播报、亮屏和上报 |

## 1. 上电上云

主板加电之后，先让 4G 上网，再向平台注册。注册成功后上报一次自身位置，然后才进入后面各章。

这一章做完的标志：

- 插上 SIM 卡，上电能自己连上 4G，断线后能再连上。
- 用模组读出的 IMEI 作为 MQTT `clientId`。干净会话，不带用户名和密码。
- 发出注册报文 `0x81`，收到 `0x00` 后保存平台给的 CID。
- 注册失败、超时、断线或被禁用时，等 30 秒，从头再来。
- 注册成功后向业务 Topic 上报一次位置。没有卫星时也上报一帧无效定位。
- 还没有 CID 时，第 2 章以后的动作一律不做。

上云报文以本节为准。《MQTT 协议 2.0.0》只作参考。注册的 `0x81`、`0x01` 和 Topic 与参考协议相同。参考协议没写清的取地址和定位，用下面两节的格式。参考协议 3.4 写的是启动后再每 5 分钟上报，整机功能列表定为本期只在注册成功后上报一次，所以这里不按 5 分钟重复。

### 1.1 板上用哪几路

上网只走 EC200A 的 USB。模组自己的主串口接到屏控 N32，主控不用那一路。调试口 `ttyS0` 是 57600，只看启动日志，不跑业务。

| 用途 | 节点 | 参数 |
|---|---|---|
| AT 口 | `/dev/ttyUSB2` | 115200。节点名以 `ec200a_test probe` 扫到的为准 |
| 上网网卡 | `usb0` | ECM，`cdc_ether`。PDP 激活后 `udhcpc -i usb0` |
| 定位 | `/dev/gps` | NMEA，9600。注册成功后读一次 |

配置在 `files/hydg02.conf`：`at_dev`、`net_if`、`gps_dev`、`firmware`、`mqtt_host`、`mqtt_port`、`http_url`、`apn`。`imei` 和 `iccid` 以模组读数为准，配置里留空。`apn` 空着就不改模组里已有的接入点。`firmware` 是注册报文里的版本字符串，以后查询版本也用这一份。

`http_url` 为空时，直接用 `mqtt_host` 和 `mqtt_port`，方便实验台。`http_url` 有内容时，每次上线都重新取地址；取失败就等 30 秒重来，不会退回 `mqtt_host`。只使用 `http://`，这一章不做 HTTPS。

```text
GET http://目录主机[:端口]/路径
HTTP/1.0，成功状态码 200
正文第一行：mqtt主机:端口
```

例如正文 `mqtt.example.com:1883`。主机只允许字母、数字、点和横线，端口必须写出。

### 1.2 上线顺序

```text
打开 AT 口，确认 SIM、信号、注网
        │
        ▼
激活 PDP，usb0 取得地址
        │
        ▼
从模组读出 IMEI、ICCID
        │
        ▼
取 MQTT 地址（http_url，或实验台配置）
        │
        ▼
连接 MQTT，clientId = IMEI
只订阅 raw/v1/cmd/auth/{IMEI}
        │
        ▼
向 raw/v1/resp/auth/{IMEI} 发送 0x81
        │
        ▼
收到 0x01
  ├─ 0x00：保存 CID，订阅该 CID 的 msg、upgrade
  │        读一次 /dev/gps，向 raw/v1/resp/msg/{CID} 发送 0x82
  └─ 0x01，或超时、断线、取地址失败、MQTT 失败：
           等待 30 秒，从 AT 口重新开始
```

4G 本身没有地址时，30 秒后从 AT 口重新开始，不只重连 MQTT。

`0x81` 的载荷是二进制：命令 `0x81`，8 字节大端毫秒时间戳，然后依次是 IMEI、固件版本、ICCID，每段前面一个长度字节。组包函数是 `src/reg_msg.c` 里的 `reg_build()`。样例字节在《MQTT 协议 2.0.0》第 2.1 节，PC 上的 `--selftest` 对的就是这一帧。

`0x01` 带回同一个时间戳。`code` 为 `0x00` 时后面才有 CID。收到成功之前，不订阅 `msg` 和 `upgrade`。

`0x82` 发到 `raw/v1/resp/msg/{CID}`，不要求平台回复。序列号是发送时的毫秒时间戳，不是注册那一帧的序列号。固定 22 字节：

```text
82
+ 序列号（8）
+ 有效（1，1 有定位，0 没有）
+ 纬度 int32 大端，单位 1e-7 度，北正南负
+ 经度 int32 大端，单位 1e-7 度，东正西负
+ UTC 时分秒 uint32 大端，083015 表示 08:30:15，无定位时为 0
```

纬度经度由 NMEA 的度分格式换算。`3112.3456 N` 是北纬 31.20576 度，报文里是 `312057600`。发送失败按断线处理。

### 1.3 程序怎么做

`src/online.c` 按第 1.2 节循环。任一步失败就关掉连接，等 30 秒，从 AT 口重新开始。

| 文件 | 作用 |
|---|---|
| `src/at_port.c` | 打开 AT 口，发送命令并等待 OK |
| `src/modem.c` | 确认 SIM 和注网，读 IMEI、ICCID，拨号，直到 `usb0` 有地址 |
| `src/mqtt_cli.c` | 连接 MQTT，订阅和发送二进制载荷 |
| `src/reg_msg.c` | 组装 `0x81`，解析 `0x01` |
| `src/http_broker.c` | 用配置或 HTTP 得到 MQTT 主机和端口 |
| `src/gps_fix.c` | 注册成功后读一次 RMC |
| `src/loc_msg.c` | 组装 `0x82` |
| `src/online.c` | 把上面几步串起来 |
| `src/main.c` | 读配置后进入这个循环 |

拨号使用 `AT+QNETDEVCTL=1,1,1`。这条失败时再试 `AT+CGACT=1,1`，然后如果网卡还没有地址就执行 `udhcpc`。

注册成功后订阅该 CID 的 `msg` 和 `upgrade`。`msg` 上的指令按第 2 章到第 7 章处理，不认识的命令回失败。`upgrade` 上的升级命令按第 7 章下载并安装。定位只在注册成功后上报一次。

N32 的组帧在 `src/n32_frame.c`，属于第 4 章。

### 1.4 怎么确认

不插板，核对注册报文和注册回复：

```sh
cd src
gcc -Wall -Wextra -std=c99 -o hydg02.exe *.c
.\hydg02.exe --selftest
```

看到 `selftest ok` 表示第 1 章到第 7 章里已经写死的报文、时段判断和 MD5 与文档一致。它不会下载升级包，也不会重启。

主板先在 `hydg02.conf` 里写上 `mqtt_host`。固件编进去之后：

```sh
/etc/init.d/hydg02 restart
logread -f
```

日志里应依次出现模组 IMEI、网卡已有地址、注册成功和 CID。没有 CID 之前，不会去动屏、喇叭和 485。可以用 `ec200a_test info` 对照日志里的 IMEI。

## 2. 语音播报

注册成功后，`raw/v1/cmd/msg/{CID}` 里的语音指令由 `src/voice.c` 执行。回执发到 `raw/v1/resp/msg/{CID}`，序列号原样带回。参考协议只要求有回执和 MD5，没有规定命令号，命令号以本节为准。

开关写在 `voice_dir/enabled`，缺文件时默认开。三个文件是同目录下的 `1`、`2`、`3`，后缀跟下载地址走。重启后还在。配置项是 `voice_dir`，默认 `/etc/hydg02/voice`。

一次手动播报按槽位 1、2、3 各放一遍就停。开关关闭，或三个槽都空，直接回失败，不先回“已开始”。下载或播报还没结束时，再来的下载、清空和播报回失败；开关和查询照常执行。

| 命令 | 方向 | 载荷 |
|---|---|---|
| `0x20` 设置开关 | 平台 → 设备 | 序号 + 1 字节，`0` 关，`1` 开 |
| `0x21` 查询 | 平台 → 设备 | 只有序号 |
| `0x22` 下载 | 平台 → 设备 | 序号 + 槽位 `1..3` + MD5 16 字节 + URL 长度 uint16 + URL |
| `0x23` 清空 | 平台 → 设备 | 只有序号 |
| `0x24` 播报一次 | 平台 → 设备 | 只有序号 |
| `0xA0` 执行结果 | 设备 → 平台 | 序号 + 原命令 + 结果码 |
| `0xA1` 查询结果 | 设备 → 平台 | 序号 + 开关 + 已有文件数 |

结果码：`0x00` 完成，`0x01` 已开始，`0x02` 失败，`0x03` MD5 不一致。下载和播报先回 `0x01`，结束再回最终结果。两次都带回原来的序号。MD5 不一致时留下旧文件。URL 必须是 `http://`，并且以 `.wav`、`.mp3`、`.pcm`、`.opus` 结尾。单文件最大 2MB。

PCM 按 48000 Hz、16 bit、单声道、小端播放。WAV、MP3、OPUS 交给播放程序，下载时不解析采样率和比特率。播放前把功放 GPIO 拉高，默认是 GPIO0，放完拉低。

播放程序是 `aplay`、`madplay`、`opusdec`。固件里还没有这几个包时，下载和校验仍然可以完成，播报回失败。主板上先看 `logread`，没有声音再看这只 GPIO 和 `aplay -l`。

## 3. 语音对讲

平台浏览器仍按参考协议走 ZLMediaKit 的 WebRTC。主板不跑 WebRTC，也不走国标 SIP。4G 出口在 NAT 后面，平台不能主动向主板拨 UDP，所以由主板先把 RTP 发到平台给出的地址，平台再把喇叭的 RTP 发回这个来源。

对讲和语音播报共用喇叭和功放。播报、下载进行时不能开始对讲。对讲进行时，播报、下载和清空回失败。语音开关不关掉对讲。

| 命令 | 方向 | 载荷 |
|---|---|---|
| `0x30` 开始 | 平台 → 设备 | 序号 + 端口 uint16 + 主机名长度 + 主机名 |
| `0x31` 结束 | 平台 → 设备 | 只有序号 |

主机名只允许字母、数字、点和横线。端口是平台收取麦克风 RTP 的 UDP 端口。

开始成功先回 `0xA0`，原命令 `0x30`，结果 `0x01`。结束后用同一个开始序号再回一次：`0x00` 是平台结束的，`0x04` 是 15 秒没有声音，`0x05` 是录音、播放或网络中断。`0x31` 自己的序号立刻回 `0x00`。还没在对讲时收到结束，回 `0x02`。

RTP 为版本 2，负载类型 96，没有扩展头。内容是 16000 Hz、16 bit、单声道、小端 PCM，一包 20 毫秒、640 字节。这在整机要求的采样率和比特率范围内。48000 Hz 的实时双向流对这块主板和 4G 过重，所以对讲不用文件播报那档 48000 Hz。

录音和播放使用 `arecord` 与 `aplay`。这两个程序不在时，开始对讲回失败。主板上看 `logread` 里的「对讲开始」和结束结果码。

## 4. LED 文字

平台下发的是 UTF-8 文字，不是点阵。主控把文字、速度和开关经 `/dev/mcu3` 发给屏控 N32，点阵由 N32 的字库生成。串口 115200，帧格式沿用《N32 与 MT 串口协议》的 `A5 5A`。走向只有由右往左，发给 N32 的走向字节固定是 `0x01`。原稿里的上下方向不再使用，也不新增 `0x03`。

参数写在 `/etc/hydg02/led.bin`。上电默认关、文字空、速度 80 毫秒。注册成功后把已保存的内容写到屏上，但不会自己滚。关闭开关后屏上不再出字，文字和速度仍留着。

| 命令 | 方向 | 载荷 |
|---|---|---|
| `0x40` 开关 | 平台 → 设备 | 序号 + 1 字节，`0` 关，`1` 开 |
| `0x41` 文字 | 平台 → 设备 | 序号 + 长度 + UTF-8，长度 0 表示清除，最长 120 |
| `0x42` 速度 | 平台 → 设备 | 序号 + 1 字节，20～200 毫秒 |
| `0x43` 显示一次 | 平台 → 设备 | 只有序号 |
| `0x44` 查询 | 平台 → 设备 | 只有序号 |
| `0xA2` 查询结果 | 设备 → 平台 | 序号 + 开关 + 速度 + 文字长度 + 文字 |

设置和显示一次的回执仍是 `0xA0`。N32 没回复、开关是关的、或没有文字，显示一次回 `0x02`。`0x00` 表示屏已经开始滚，滚完自己停在空白，这里不再等滚完。查询回的是主控保存的参数。

屏口 300 毫秒没有回复就重发，最多再发 2 次。滚动过程中如果屏上报触发，先回屏，动作按第 5 章执行。

## 5. 触发与定时

红外/雷达由屏控 N32 从 `PIR-IN` 报上来，命令 `0x90`。主控在 200 毫秒量级回 `0x8F`，同一个序号只执行一次。信号一直保持时，N32 自己不会重复报。

触发方式、定时开关和允许时段写在 `/etc/hydg02/trig.bin`。默认是红外/雷达，定时关闭，时段预置为 07:00–18:00 但不生效。定时打开后用主板本地时间判断，结束时刻不算在时段内。22:00–06:00 这种跨午夜的时段可以。主板时钟不准时，时段会跟着偏；这一章不改系统时间。

语音开关关着就不播，显示开关关着或没有文字就不滚。两个都关、不在时段、或正在播报/对讲，这次不执行。语音开关开着但没有文件，算这次失败。摄像机人车事件是下一版，方式切过去之后雷达仍会应答，但不再播、不再亮、也不再上报。

| 命令 | 方向 | 载荷 |
|---|---|---|
| `0x50` 触发方式 | 平台 → 设备 | 序号 + 1 字节，`0` 红外/雷达，`1` 摄像机 |
| `0x51` 时段 | 平台 → 设备 | 序号 + 定时开关 + 开始时 + 开始分 + 结束时 + 结束分 |
| `0x52` 查询 | 平台 → 设备 | 只有序号 |
| `0x53` 手动触发 | 平台 → 设备 | 只有序号 |
| `0xA3` 查询结果 | 设备 → 平台 | 序号 + 方式 + 定时开关 + 开始时分 + 结束时分 |
| `0xA4` 触发结果 | 设备 → 平台 | 新序号 + 来源 + 结果码 |

来源 `1` 是雷达，`2` 是手动。结果码仍是 `0x00` 成功、`0x02` 失败。手动触发先回 `0xA0` 的已开始，做完再回最终结果，并另发一条 `0xA4`。

## 6. RS485 转发

主控有两路 RS485。`1` 是 `/dev/rs485`，`2` 是 `/dev/rs485_6`。方向由驱动控制，程序只按配置里的波特率原样收发，默认 9600。不解析 Modbus，地址和校验都由平台放在报文里。

| 命令 | 方向 | 载荷 |
|---|---|---|
| `0x60` 转发 | 平台 → 设备 | 序号 + 端口 + 超时毫秒 uint16 + 长度 uint16 + 原始字节 |
| `0xA5` 转发结果 | 设备 → 平台 | 原序号 + 结果码 + 长度 uint16 + 现场返回的原始字节 |

超时允许 50～3000 毫秒。请求最长 256 字节，收回来的也最多 256 字节。发出前先丢掉口里残留的旧字节。收到第一个字节后再安静 20 毫秒，就把已经收到的当作这一次的应答。现场没有回数据时，结果仍是 `0x00`，长度为 0。口打不开、正在转发另一条，或写出失败，回 `0x02`。

主板上不提供 RS232 电平。RS232 设备要在现场另加电平转换。

## 7. 升级、远程重启、恢复出厂

升级走单独的主题。平台发到 `raw/v1/cmd/upgrade/{CID}`，进度和结果发到 `raw/v1/resp/upgrade/{CID}`。重启、恢复出厂和版本查询走业务主题 `raw/v1/cmd/msg/{CID}`，回执仍回业务应答主题。版本字符串就是配置里的 `firmware`，和注册报文里的那一份相同。

| 命令 | 主题 | 载荷 |
|---|---|---|
| `0x70` 升级 | upgrade | 序号 + MD5 16 字节 + URL 长度 uint16 + `http://` 地址 |
| `0x71` 重启 | msg | 只有序号 |
| `0x72` 恢复出厂 | msg | 只有序号 |
| `0x73` 版本查询 | msg | 只有序号 |
| `0xA6` 版本结果 | msg | 序号 + 长度 + 版本字符串 |

升级先回 `0x01`。MD5 不一致回 `0x03` 并删掉半截文件，继续跑当前版本。下载失败或 `sysupgrade` 拒绝镜像，回 `0x02`。校验通过且安装程序已启动，回 `0x00`，随后主板重启，再用新版本重新注册。升级包最大 15MB，先放在 `/tmp/hydg02-upgrade.bin`。配置和已保存的语音、屏幕、触发参数会保留。

升级过程中，播报、对讲、显示、触发和 485 转发都回失败。版本查询仍然可以。

恢复出厂删掉语音文件、`led.bin` 和 `trig.bin`，不改 `hydg02.conf` 里的平台地址。删完回 `0x00` 并重启。远程重启只重启，不删这些参数。两边都调用 `/sbin/reboot`。
